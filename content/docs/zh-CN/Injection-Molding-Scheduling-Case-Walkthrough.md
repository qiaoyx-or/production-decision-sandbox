# 注塑排程案例：让颜色、盖型与容量进入换型决策

本案例使用 `InjectionMoldingWorkshop/data.db` 与官方 `production_scheduling` 配方。2026-08-31 只读检查确认数据库完整性为 `ok`，其中有 37 条需求、2 个工作中心、115 种物料、418 条工艺适配和 120 条既有结果记录。

## 1. 输入语义

标准属性槽位在配方中映射为颜色、盖型和容器容量。这个映射使模型直接处理业务属性，避免依赖 `property_1`、`property_2` 这类存储位置猜测含义。

## 2. 约束与切换

配方选择循环序列排程，引入产能、需求、库存、序列切换和循环切换约束。序列内相邻任务按颜色计算切换，复用产能周期之间按容器容量表达状态变化。上线前还执行整数化和批量倍数检查，发现不一致即停止，不把错误数据带入求解。

## 3. 运行配置

工作中心为 2，序列长度 40，循环次数 3，目标权重为颜色 0.1、容量 1，求解请求为 16 线程、60 秒。这里的数字属于标准样例配方，实际现场应根据设备、工艺和管理目标重新确认。

## 4. 输出与验收

| 输出 | 阅读方式 | 验收问题 |
|---|---|---|
| 排程序列 | 按工作中心和循环查看任务顺序 | 序列长度和任务范围是否正确 |
| 需求覆盖 | 对照 37 条需求 | 是否存在未排或重复任务 |
| 序列切换 | 统计相邻颜色变化 | 减少切换是否造成其他代价 |
| 循环切换 | 检查循环首尾容量状态 | 周期复用是否保持合理衔接 |
| 批量审计 | 对照生产率与需求倍数 | 预处理是否发现不一致 |
| 目标材料审计 | 检查颜色和容量方向 | 权重是否按配置进入求解 |

重算时一次只调整颜色/容量权重、序列长度或循环次数中的少量参数，避免无法解释差异来源。

## 5. 证据边界

2026-08-31，本案例在隔离的商业版副本中使用有效 `Enterprise` 授权完成了真实 A/B 运行。两次 API 运行均采用 16 线程、60 秒上限，返回 `ok`、1 个候选解、有效最佳方案、120 条结果和 12 个动作事件，错误数为 0。基线耗时 66.57 秒，调整方案耗时 66.50 秒；该时间包含 Web API 外层处理，不应直接解释为纯求解器耗时。

基线配置为 `color=0.1`、`capacity=1.0`，结果分析得到 41 次序列切换、6 次循环切换，加权切换成本为 14.9。调整方案为 `color=0.8`、`capacity=1.5`，结果为 46 次序列切换、14 次循环切换，加权切换成本为 66.4。两次方向审计均通过，分析值与 GOCK 目标材料值一致。

这个结果没有被包装成“提高权重就一定减少切换”。相反，它展示了重算后必须重新查看业务结果：样例目标材料统计包含原生材料单位和空状态转换，权重变化也会改变不同取舍的相对代价。权重表达决策偏好；展示指标是否变化，还取决于数据、约束和其他目标之间的共同作用。
