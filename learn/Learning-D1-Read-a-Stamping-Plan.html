D1 冲压计划：把需求、产能与齐套放在一起看

本页内容
从订单需求追到资源和物料输入不是一张订单表约束与执行流程读懂基线与调整页面截图怎样使用练习与参考解析延伸阅读

从订单需求追到资源和物料

冲压计划需要同时回答：哪些时段能够完成需求，工作中心是否有足够产能，相关工序的物料是否可用。本例使用StampingWorkshop/data.db及production_planning能力编排配方（recipe），沿输入、配置和结果逐步检查这些问题。

案例运行于2026-08-31，版本为DecisioWorks v1.4.0，采用商业版Enterprise授权。以下表格保留该次运行的参数和结果，便于对照阅读。

输入不是一张订单表

对象 已记录规模 在计划中起什么作用
订单明细 1920条 制品、交期与需求数量
产能记录 50条 时间与工作中心可用条件
工序物料关系（ingredient） 38条 各工序所需的物料及消耗关系
齐套记录 500条 物料可用时间与数量
时间单元 25个 输入与结果共同时间坐标
工作中心 3个 资源范围

先选一条订单，追到制品、路线、工序及可执行资源；启用齐套时，再检查相应物料条件。各表行数用于检查导入是否完整；进一步核对引用关系，才能确认订单已经连接到相应的资源和物料。

约束与执行流程

本记录启用产能、需求和齐套约束，产能采用软约束，库存约束关闭。基线目标为job_bias=-0.001、waittime=1.0；求解请求为16线程、120秒。参数属于该次记录，实际使用遵循当前版本与授权范围。

流程为数据采集、约束解析、方案生成、方案选择、结果评估和可选结果输出。结果输出使用独立文件，不依靠覆盖标准业务数据库。

读懂基线与调整

项目 基线 调整方案
job_bias权重 -0.001 -0.003
waittime权重 1.0 2.0
API返回状态 ok ok
API耗时（秒） 14.41 14.29
结果行数 66 66
总需求/总产出 680500/680500 680500/680500
最终短缺 0 0
job_bias加权贡献 -7854.678 -23564.034

基线记录中，可用产能1188000，加工负荷371588.48，含准备与等待的计划负荷377080.42，报告利用率约31.74%。这些负荷数值保留报告口径，未在本课换算为分钟。

两次运行均选出经检查有效的候选方案；这里的“最佳”指本次运行选中的候选，不表示已证明全局最优。所列总体指标一致，下一步可按业务标识对齐明细，检查数量与完成时点是否也一致，并将完成时点与交期比较。两项权重同时变化，本记录反映的是组合调整的结果。

页面截图怎样使用

参考资料包含真实输入、基线和对比截图。页面记录采用2线程、60秒，是与上述API不同的一组运行。阅读时保持每组配置与结果对应，不把截图数字拼接到API表中。

练习与参考解析

阅读练习：只用上文数字，复核以下两项。

检查项 人工复算 解释
总体利用率 377080.42 ÷ 1188000 × 100 ≈ 31.74% 与报告的总体利用率一致；局部是否超载还需查看时段明细
计划负荷与加工负荷之差 377080.42 − 371588.48 = 5491.94 按报告定义，两者的差涉及准备与等待；不能据此分别确定两项数值

这里复算的是已发表记录，负荷继续使用报告原有单位。表中没有提供分钟换算依据。

参考结论可写为：“两次运行的总产出均为680500，最终短缺均为0；现有汇总可以确认这两项数量结果一致。是否同样准时、是否有局部超载，以及任务时点是否改变，需要继续查看明细。”

操作练习：取得结果明细后再完成。 在同一运行组中选择一个工作中心与时间单元，填写需求、产能、物料条件、结果和待检查事项。只有汇总表时，将这一步标为“待取得明细”，不推算不存在的逐行结果。

后续可设计只改变waittime的比较：固定数据、约束、其他目标及运行条件，并检查最终生效的目标配置。另行保存新运行的状态、结果和明细差异，再判断该项变化的影响。
