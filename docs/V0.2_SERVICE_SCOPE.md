# Production Decision Sandbox V0.2 服务范围补充方案

> 版本：V0.2 补充稿  
> 日期：2026-08-24  
> 主题：围绕 DecisioWorks 的外围服务系统、GitHub Pages 公开主页与本地沙盘边界

---

## 1. 总体定位

Production Decision Sandbox 不是另一个 APS 系统，也不是 DecisioWorks 的替代品。它是围绕 DecisioWorks 建设的外围服务系统，承担可视化、诊断、编排、案例、提示词、教学和公开传播职责。

它解决的问题是：让外部用户在不接触 GOCK 内核、不进入重型项目实施、不依赖口头说明的情况下，看见 DecisioWorks 如何从输入数据进入生产决策链路，并理解自己可以如何开始验证、学习、集成和共建。

核心边界如下：

| 层级 | 职责 | 是否公开 | 是否运行真实数据 |
|---|---|---|---|
| GitHub Pages 公开主页 | 项目介绍、能力地图、教程入口、静态样例、模板索引 | 公开 | 否 |
| 本地 Sandbox 工作台 | 数据诊断、流程编排、规则案例、教学练习、运行复核 | 面向授权或试点对象 | 可在本地或客户内网运行 |
| DecisioWorks Adapter | 能力注册、配方转换、授权调用、结果标准化、证据回传 | 不作为公开入口 | 是 |
| DecisioWorks / GOCK | 标准化数据接口、模型能力、受控求解、结果分析 | 按授权边界 | 是 |

一句话：公开主页负责被理解，本地沙盘负责被验证，DecisioWorks 负责真实能力链，GOCK 保持受控内核边界。

## 2. V0.2 核心模块

### 2.1 可视化流程编排

流程编排器的目标不是做通用低代码平台，而是把 DecisioWorks 的标准动作、能力配方和运行链路转化为可视化工作台。

首期能力：

- 展示数据诊断、业务映射、目标配置、边界控制、受控求解、结果分析、反馈迭代等节点；
- 节点来源于 DecisioWorks 能力注册表，不允许用户创建任意脚本节点；
- 连线时校验输入输出类型，避免把不可连接的能力硬拼到一起；
- 每个节点保留输入对象、输出对象、参数、状态、错误、耗时和证据摘要；
- 支持只读运行轨迹、模板复制和配方导出；
- 导出格式优先采用可校验 YAML / JSON，而不是生成不可治理的临时代码。

编排器的价值不是“拖拽好看”，而是让客户和伙伴看清一条生产决策链路如何被组织、校验、运行和复用。

### 2.2 输入数据诊断

输入数据诊断是 Sandbox 的第一核心能力。它不只检查字段是否存在，更重要的是判断数据是否具备进入 DecisioWorks 能力链的条件。

诊断分为五层：

| 层级 | 判断重点 | 输出 |
|---|---|---|
| 文件与结构 | 文件、表、字段、类型是否可读取 | 缺表、缺字段、类型错误 |
| 业务语义 | 单位、时间、数量、状态含义是否一致 | 语义缺口、单位冲突、枚举缺失 |
| 关系闭合 | 订单、产品、工艺、资源、物料、日历能否关联 | 孤立对象、断裂关系、不可执行工序 |
| 约束可用 | 产能、班制、维护、齐套、批量等能否构成约束 | 阻断项、警告项、建议项 |
| 求解就绪 | 是否达到 ContractReady、ModelReady、SolverReady | 阶段结论与修复顺序 |

诊断结果应能定位到表、字段、记录和业务关系，并说明为什么这个问题会影响后续建模、求解或结果解释。

### 2.3 经验、偏好与规则案例库

案例库用于把现场经验从口头判断转化为可复核、可插入、可比较的能力资产。界面可以使用“经验、偏好与规则”这样的业务语言，工程详情中标注 `marginal_control`、`objective_system`、`planning_system` 等归属。

首批案例建议覆盖：

- 设备维护窗口避让；
- 冻结窗口与局部重构；
- 紧急订单插入与已有承诺保护；
- 共享设备、模具、人员或工装协调；
- 瓶颈资源保护与非瓶颈任务释放；
- 缺料条件下的订单释放与延期取舍；
- 同类产品连续生产与换型成本控制；
- 交付、库存、负荷、等待和切换之间的目标取舍。

每个案例至少包含业务问题、适用场景、所需数据、表达方式、可调参数、预期影响、风险提示和验证证据。案例可以插入流程编排，但不能绕过参数确认、授权边界和人工复核。

### 2.4 AI Agent 提示词生成

AI Agent 提示词模块不应只生成一段泛化提示词，而应生成结构化任务包。它的作用是让 AI Agent 在明确边界内辅助完成数据映射、诊断、配置、运行、排障、报告和教学任务。

任务包建议包含四类文件：

| 文件 | 用途 |
|---|---|
| `AGENT_TASK.md` | 人可读任务说明 |
| `context.json` | 结构化上下文 |
| `acceptance.md` | 验收条件 |
| `allowed-actions.json` | 允许动作与禁止动作 |

任务包必须明确：项目名称、数据范围、能力配方、允许访问路径、禁止动作、脱敏要求、验收标准和预期输出格式。

禁止内容包括：私钥、授权文件、客户原始数据、GOCK 内部实现、内部绝对路径和未经授权的求解调用方式。

### 2.5 DecisioWorks 使用教学

教学中心服务于制造企业、咨询伙伴、系统厂商和 AI Agent 使用者。教学不是静态说明书，而是围绕真实样例形成“解释、操作、运行、检查、复盘、模板沉淀”的练习链路。

首期学习路径：

| 路径 | 学习目标 | 产出 |
|---|---|---|
| 30 分钟快速开始 | 启动样例并看懂一次结果 | 一次完整运行记录 |
| 数据接入人员 | 理解标准数据接口与关系闭合 | 数据诊断报告 |
| 计划与排程人员 | 配置目标、规则和边界 | 可复核排程结果 |
| 实施与生态伙伴 | 建立试点流程和模板 | 试点材料包 |
| AI Agent 使用者 | 生成、审核和验收任务包 | 可复用提示词任务包 |

教学内容必须连接可运行样例，避免用静态截图替代运行证据。

## 3. GitHub Pages 主页设计补充

GitHub Pages 主页用于公开传播和学习入口，不承载客户数据，不执行真实求解，也不暴露授权链路。

### 3.1 首页结构

推荐首页采用七段式结构：

1. **首屏识别**：Production Decision Sandbox / 生产决策沙盘，说明它是 DecisioWorks 的可视化试点、教学与生态入口；
2. **五步路径**：数据诊断 → 流程编排 → 规则表达 → 运行复核 → 模板沉淀；
3. **数据诊断示例**：展示 ContractReady / ModelReady / SolverReady 阶段判断；
4. **流程编排预览**：展示只读流程画布、节点状态和运行轨迹；
5. **案例库入口**：展示维护避让、冻结窗口、瓶颈保护、缺料释放等示例；
6. **AI Agent 与教学入口**：展示结构化任务包和分角色学习路径；
7. **项目与下载入口**：链接 DecisioWorks Research、版本说明、SHA256 校验、公众号和联系方式。

### 3.2 推荐页面路由

| 路径 | 页面 | 内容 |
|---|---|---|
| `/` | 首页 | 产品定位、五步路径、核心入口 |
| `/data-diagnosis/` | 数据诊断 | 脱敏样例、阶段判断、问题清单 |
| `/flow/` | 流程编排 | 只读流程画布、节点说明、Recipe 示例 |
| `/control-cases/` | 规则案例 | 经验、偏好、规则案例库 |
| `/agent/` | AI Agent | 任务包结构、提示词模板、禁止动作 |
| `/learn/` | 学习路径 | 分角色课程与练习 |
| `/templates/` | 样例模板 | 数据、流程、报告、教学模板 |
| `/downloads/` | 下载 | 版本、校验、公开项目地址 |
| `/contact/` | 联系 | 公众号、邮箱、合作方式 |

如果首期不做多页面，也可以用单页锚点实现，后续再拆成专题页。

### 3.3 公开数据模型

公开主页只使用静态 JSON，建议包含 `capability-map`、`diagnosis-examples`、`flow-examples`、`control-cases`、`agent-templates`、`lessons` 和 `downloads` 等内容。

这些 JSON 只保存公开说明、脱敏样例和静态预览状态，不保存客户数据、运行日志、授权信息和内部路径。

### 3.4 首期上线标准

- 首屏 10 秒内说明产品与 DecisioWorks 的关系；
- 首页至少提供数据诊断、流程编排、规则案例、AI Agent、教学五个入口；
- 所有样例标注状态：静态说明、ContractReady、ModelReady、SolverReady 或端到端已验证；
- 移动端无文字遮挡、箭头错位和横向溢出；
- 页面不包含客户数据、授权材料、内部路径和商业秘密；
- 下载内容附版本、文件大小和 SHA256 校验；
- 提供 404、站点地图、基础 SEO 与 Open Graph 图片。

## 4. 转化型能力设计

Sandbox 的 V0.2 重点不是“功能更多”，而是把 DecisioWorks 的能力转化为可触达、可试点、可集成、可传播的产业入口。

### 4.1 场景卡

每一个对外沟通入口都应尽量落到场景卡。场景卡包含业务问题、所需数据、可验证结果、适用对象和下一步动作。它把抽象的生产决策能力变成客户能判断、伙伴能转交、内部能跟进的最小单元。

### 4.2 数据资产评分

数据诊断完成后，应输出结构完整度、语义清晰度、关系闭合度、约束可用度和运行就绪度评分。评分结果要给出阻断项、修复顺序和下一步建议，使客户在进入正式试点前就能获得数据资产层面的明确反馈。

### 4.3 证据包

每次运行都应形成证据包，记录数据版本、场景卡、配方、参数、授权状态、运行结果、分析结论和人工复核意见。证据包用于复盘、沟通、试点证明和模板沉淀，不包含客户敏感明细、授权密钥和 GOCK 内部实现。

### 4.4 伙伴集成包

面向 MES / ERP / WMS 厂商、工业互联网平台和系统集成商，应提供独立的伙伴集成包，说明数据如何导出、接口如何映射、Adapter 如何调用、结果如何嵌入、证据如何回传、授权边界如何控制。

### 4.5 咨询伙伴工作流

面向咨询机构，应提供“场景识别 → 数据收集 → 数据诊断 → 成熟度判断 → 目标与规则配置 → 运行验证 → 效果评估 → 试点建议”的工作流。它让咨询服务从方案说明推进到可验证结果。

### 4.6 AI Agent 模板库

AI Agent 模板库按数据映射、诊断、编排、排障、对比解释、报告生成和教学练习分类。每个模板都要包含上下文、允许动作、禁止动作、输出格式和验收标准。

### 4.7 公开页转化漏斗

GitHub Pages 应从“项目展示页”升级为轻量转化漏斗：看懂定位、浏览样例、下载研究版、整理场景卡、查看集成包、进入本地验证或商业授权沟通。


## 5. 实施优先级

建议按“先诊断、再编排、后教学与传播”的顺序推进：

1. **P0：公开主页骨架**。先把 GitHub Pages 首页、项目定位、五步路径和下载入口做出来。
2. **P1：数据诊断工作台**。建立样例数据读取、字段检查、业务关系闭合、阶段判断和报告导出。
3. **P2：只读流程编排**。先展示固定 Recipe、节点状态和运行轨迹，不急于开放拖拽编辑。
4. **P3：规则案例库**。将 `marginal_control` 相关经验案例做成卡片和参数示例，形成差异化资产。
5. **P4：AI Agent 任务包**。基于当前项目、数据、流程和验收标准生成可复制任务包。
6. **P5：教学中心**。把可运行样例组织成分角色课程，用于伙伴培训和客户试点前置沟通。
7. **P6：Adapter 与真实运行**。在本地或客户内网通过 DecisioWorks Adapter 接入真实能力链，形成证据包。

## 6. 对外表达边界

可以表达：

- Production Decision Sandbox 是 DecisioWorks 的可视化试点、教学与生态入口；
- 它帮助用户先看清数据、再组织流程、再验证结果；
- 它把经验、偏好和规则沉淀为可复核案例；
- 它可以生成 AI Agent 任务包，辅助数据诊断、配置、排障和报告；
- 它服务于制造企业、咨询伙伴、MES/ERP 厂商、系统集成商和产业渠道。

避免表达：

- 它是完整 APS 替代品；
- 它在线处理客户真实数据；
- 它公开 GOCK 内核；
- 它让 AI 自动承担生产决策责任；
- 它绕过 DecisioWorks 授权直接调用求解能力。
