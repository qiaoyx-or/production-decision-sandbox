查看颜色、盖型与容器容量如何进入循环排程及换型结果对比。

适用于 DecisioWorks v1.4.0

注塑排程案例：让颜色、盖型与容量进入换型决策

本案例使用 InjectionMoldingWorkshop/data.db 与 production_scheduling 能力编排配方（recipe），展示产品属性怎样影响循环排程与换型取舍。2026-08-31 的样例包含 37 条需求、2 个工作中心、115 种物料、418 条工艺适配和 120 条既有结果记录，数据库完整性检查通过。既有结果是输入文件中的历史记录，应与本次求解新生成的结果分别查看。

1. 输入语义

标准属性槽位在配方中映射为颜色、盖型和容器容量。这里的容量指制品的容器容量，不是设备产能。这个映射使模型直接处理业务属性，避免依赖 property_1、property_2 这类存储位置猜测含义。

2. 约束与切换

配方选择循环序列排程，引入产能、需求、库存、序列切换和循环切换约束。序列内相邻任务按颜色计算切换，复用产能周期之间按容器容量表达状态变化。求解前执行整数化和批量倍数检查；不满足要求时，先修正对应数据再运行。

3. 运行配置

工作中心为 2，序列长度 40，循环次数 3，目标权重为颜色 0.1、容量 1，求解请求为 16 线程、60 秒。这里的数字属于标准样例配方，实际现场应根据设备、工艺和管理目标重新确认。

4. 输出与验收

输出 阅读方式 验收问题
排程序列 按工作中心和循环查看任务顺序 序列长度和任务范围是否正确
需求覆盖 对照 37 条需求 是否存在未排或重复任务
序列切换 统计相邻颜色变化 减少切换是否造成其他代价
循环切换 检查循环首尾容量状态 周期复用是否保持合理衔接
批量审计 核对单次出件数、批量及模型要求的整数倍关系；需求量不必是批量的整数倍 预处理是否发现不一致
目标材料审计 检查颜色和容量方向 权重是否按配置进入求解

重算时一次只调整颜色/容量权重、序列长度或循环次数中的少量参数，避免无法解释差异来源。

5. 实际运行与结果对比

以下记录来自 2026-08-31 的 DecisioWorks v1.4.0 商业版 Enterprise 授权运行。两次 API 运行均采用 16 线程、60 秒上限，返回 ok、1 个有效候选方案、120 条新生成结果和 12 个动作事件，错误数为 0。成功返回可用方案不表示已证明全局最优。基线耗时 66.57 秒，调整方案耗时 66.50 秒；该时间包含 Web API 外层处理，不应直接解释为纯求解器耗时。

基线配置为 color=0.1、capacity=1.0，结果分析得到 41 次序列切换、6 次循环切换，加权切换成本为 14.9。调整方案为 color=0.8、capacity=1.5，结果为 46 次序列切换、14 次循环切换，加权切换成本为 66.4。两次方向审计均通过，分析值与 GOCK 目标材料值一致。

调整后，两类切换次数都增加了，因此这组记录不能作为“增加权重就能减少换型”的依据。两次加权成本使用不同权重，也不宜直接据此判断方案优劣。样例的目标材料还包含模型自身的计量项和空状态转换，不能仅用页面切换次数乘权重还原。复核时应结合任务序列、约束满足情况和实际换型代价判断是否接受新方案。

在这次样例环境中，页面以 2 线程请求运行时未成功，以数据集默认的 16 线程运行时，基线与调整重算均完成。复查样例时需要同时记录线程数、时间上限、数据版本和约束配置；这项观察不表示 16 线程是所有场景的最低要求，也不保证相同资源在不同环境中得到相同结果。

API 证据与页面截图是两组独立的真实运行。并行搜索可能返回不同的可行序列，因此截图中的切换次数不要求与 API 摘要逐项相同；每组 A/B 只在自身同一执行环境和参数口径内比较。
