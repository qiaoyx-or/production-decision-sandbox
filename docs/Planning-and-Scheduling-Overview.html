理解主生产计划、任务释放和作业排程之间的职责分工。

适用于 DecisioWorks v1.4.0

计划与排程：两个层级如何保持一致

主生产计划和作业排程分别处理不同层级的问题。主生产计划决定一段时期内“生产什么、生产多少、何时释放”；作业排程在已经释放、可执行的任务范围内决定“由哪个资源、按什么顺序、在什么时间加工”。把两者塞进一个模型，往往会让计划过细、排程承担物料和管理矛盾，并在扰动出现后失去稳定性。

主生产计划承担什么

主生产计划汇聚需求、产能、物料、库存、交付承诺和执行反馈。它不追求每道工序的秒级精确，而是识别欠产、超载、齐套风险、库存压力和承诺风险，决定哪些任务可以释放，哪些需要等待、调整或升级处理。

在 DecisioWorks 中，这些变化可形成计划偏差量（PlanBias）。偏差记录来源、对象、方向和影响，不直接覆盖原计划，使计划员能够先理解变化，再决定动作。

作业排程承担什么

作业排程接收已释放、已确认、物料条件基本满足的任务包，在局部生产单元内处理资源分配、先后顺序、等待、空闲和换型。排程越精确，对输入稳定性的要求越高，因此不应让排程器同时承担长期预测、采购承诺和跨部门协调。

两者怎样联动

需求、产能、物料和执行变化
  -> PlanBias
  -> PlanSignal
  -> 目标或规则候选 / 释放策略
  -> 排程任务包
  -> 负荷、等待、切换和执行反馈
  -> 下一轮计划

PlanSignal 是可路由的影响信号。它可以改变目标权重，形成局部规则，影响任务释放，也可以只作为预警保留。这样，变化不会未经判断就直接改写整张计划。

冻结、延续与重构

扰动响应不应默认全局重排。临近执行且已经准备完成的任务通常需要冻结；仍然合理的部分应延续；只有受影响且确有必要的范围才进入重构。评估时应同时比较新方案收益、调整范围、现场切换成本和承诺影响。

如何在 Web 中观察

  1. 在场景实验台检查需求、产能、齐套和时间单位。
  2. 运行基线方案，查看满足、负荷、等待与短缺。
  3. 调整一个目标、规则或资源条件后重算。
  4. 比较哪些任务保持稳定、哪些发生变化以及变化原因。
  5. 将需要跨周期处理的问题记录为下一轮计划输入。

常见误区

  • 把主生产计划当成更粗的甘特图；
  • 把缺料和采购矛盾全部留给排程器；
  • 发现异常就覆盖原计划，无法说明调整原因；
  • 只比较目标分数，不比较计划稳定性和执行代价。
