区分可读取、关系完整与可进入求解链路的不同阶段。

适用于 DecisioWorks v1.4.0

数据准备与校验：从能导入到能决策

数据能被读取，只证明文件和字段可访问；它并不证明业务关系正确，更不证明模型可以求解。DecisioWorks 将数据接入拆成连续验收阶段，使问题尽量在进入求解器之前暴露。

五级就绪状态

状态 要回答的问题 典型证据
ContractReady 表、字段、类型和标识能否识别 结构报告、必填字段检查
RelationReady 时间、制品、工艺、资源和物料关系能否闭合 外键与关系链报告
ModelReady 业务事实能否转成模型对象和结构约束 能力组装与约束清单
SolverReady 目标、规则和运行配置能否组成可求解问题 配方检查、目标材料审计
DecisionReady 结果能否被业务人员解释、比较和确认 结果下钻、复盘记录

这些状态分别对应不同风险的验收结论。某个数据集可以达到 ContractReady，但仍因缺少工艺顺序、产能或目标材料而无法达到 SolverReady。

四条关系链检查

  1. 时间链：交期、产能、齐套和结果采用一致的 time_unit、比例和时间单位。
  2. 制品链：订单、工艺路线、库存和属性指向同一制品身份。
  3. 工艺产能链：制品经路线、工序和 process_adaptor 找到可执行工作中心。
  4. 物料链：工序级物料需求能够与物料、库存或齐套信息对应。

数值与单位检查

  • capacity.used 使用 0 到 1 的已占用比例；分钟和百分数整数应使用各自对应的字段与单位；
  • 订单数量、批量和生产率需要使用一致的数量口径；
  • 加工时间、交期和日历必须说明单位；
  • 目标权重是取舍系数，不能当成实际负荷、短缺或时间；
  • 枚举值和状态码应有来源系统与标准语义映射。

校验失败怎样处理

校验结果应指出对象、字段或关系位置，并给出修复方向。不要在映射层静默补默认值，也不要为了让求解通过而制造不存在的业务事实。确有业务缺省时，应由数据责任人确认，并在映射说明中保留来源和假设。

ERP、MES 数据接入建议

先按业务对象建立映射表，再处理系统字段。订单可能来自 ERP，执行和设备状态来自 MES，库存与来料来自 WMS 或采购系统；标准接口负责把它们组织到共同语义，不要求某个来源系统成为 APS 的绝对前置条件。

验收输出

一次完整数据验收应保留数据版本、映射规则、行数统计、关系错误、单位说明、就绪状态和未解决问题。只有达到 SolverReady 的数据集，才应出现在可直接求解的场景入口中。
